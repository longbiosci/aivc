# 运行落账（run ledger）

每个定时任务结束时，**无论成败**，调用一次：

```bash
python3 tools/report_run.py --task <content|ops|deep|scan|review> \
  --status <ok|noop|blocked|failed> \
  --summary "<一句话结论>" [--note "<补充>"] \
  [--sha <短SHA>] [--branch <分支>] [--pr <编号>]
```

## 为什么有这个文件

2026-10-31 之前，五个定时任务各跑各的沙箱，报告输出到「可能没人看」的地方。真实后果：

- 任务因网络抖动 `git push` 失败，重试循环里 `&&` 把错误吞掉，任务「跑完了」、分支根本没推上去，**没有任何人知道**；
- 07:00 晨审只能靠翻 PR 列表反推昨夜发生了什么，翻不到就等于昨夜没发生；
- 任务失败 vs 任务无事可做，在外部看来是同一个结果——**这是虚假绿灯的温床**。

## 状态语义（务必区分）

| status | 含义 | exit | 晨审怎么处理 |
|---|---|---|---|
| `ok` | 有产出，已推送 / 已开 PR | 0 | 正常审查 |
| `noop` | **确实没有值得发布的内容**，主动不提交 | 0 | 正常，不算异常 |
| `blocked` | 环境或依赖阻断（拿不到仓库、网络不通、令牌失效） | 1 | **必须点名报警**，不得当作「今日无内容」 |
| `failed` | 执行出错（校验红、脚本崩、推送失败） | 1 | **必须点名报警** |

> `noop` 和 `blocked` **绝不能混用**。把阻断写成 noop，就是 AGENTS.md 事故备忘里
> 「2026-10-28 环境阻断但报告沉默」的复发。

## 落账位置

默认 `/workspace/.intel/`：`runs.jsonl` 追加一行 JSON，`blocked` / `failed` 另存一份
`ALERT-<task>-<时间>.txt`，让晨审一眼看到红色。

沙箱不跨实例共享，所以晨审读不到时**以 GitHub 上 PR / Issue 为准**——本文件是旁证，不是唯一事实源。
